# 💜 Project SHION Versioning Strategy

Version: 1.0.0

Last Updated: 2026-07-20

---

# Overview

This document defines how Project SHION versions are managed.

Version numbers represent meaningful milestones in the evolution of SHION rather than the quantity of implemented features.

---

# Version Format

Project SHION follows Semantic Versioning.

MAJOR.MINOR.PATCH

Example

v1.0.0

---

# Major Version

Increase when SHION fundamentally evolves.

Examples

- First public release
- Major architecture redesign
- Significant AI capability improvements

---

# Minor Version

Increase when new features or modules are added.

Examples

- New Live2D functionality
- Memory improvements
- Desktop features
- Voice integration

---

# Patch Version

Increase when fixing bugs or improving documentation.

Examples

- Typo corrections
- Documentation updates
- Minor implementation fixes

# Release Philosophy

A new version should reflect meaningful progress.

Avoid increasing version numbers for insignificant changes.

---

# Changelog

Every version should be accompanied by an update in CHANGELOG.md.

Changes should be categorized as

- Added
- Changed
- Fixed
- Removed

---

# Philosophy

A version number is not just a label.

It tells the story of SHION's growth.
